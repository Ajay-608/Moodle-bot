MOODLEBOT — CURRENT DEPLOYMENT READINESS
========================================

Production target (planned, not deployed):

Internet
  -> Nginx
  -> Gunicorn
  -> Django
  -> Amazon RDS PostgreSQL

Production initialization uses a fresh PostgreSQL database. The old SQLite
database is local/archive data only and is not migrated. Existing SQLite
users/profiles, chats/messages, Documents, feedback, learning gaps, surveys,
and primary keys will not appear in PostgreSQL. A new superuser is created
directly in PostgreSQL; users register normally after launch.

The committed media/*.txt files are the production knowledge source.
`python manage.py initialize_knowledge_base` creates new Documents and chunks
on a fresh database and refuses to run if any Documents already exist.
PostgreSQL assigns fresh Document IDs. Run `python build_index.py` afterward
to create a new FAISS index using all-MiniLM-L6-v2 (384 dimensions) and mapping
PostgreSQL Document.id values to FAISS IDs. The old `rag_index.faiss` is not
used.

Fresh PostgreSQL initialization steps and required environment variables:
`docs/fresh-postgresql-initialization.md`

`populate_sample_data` is local-development-only. Destructive legacy content
loaders are not part of production initialization or normal deployments.
Optional SQLite migration/export scripts are retained as legacy local tools
only; production does not depend on them.

AWS RDS, EC2, DNS, HTTPS, Nginx/Gunicorn deployment, and PostgreSQL
connectivity have not been created, configured, or tested. No AWS resource
identifiers, addresses, endpoints, or credentials are specified here.

Historical Render deployment notes were intentionally removed from this
current-readiness summary. The old deployment is not the production target.
